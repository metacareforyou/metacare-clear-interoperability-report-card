# MetaCare Clear interoperability report card

This repository publishes the results of running the ONC Inferno Da Vinci test kits against MetaCare Clear. It also lists every defect we found in the test kits and in the HL7 guides, each drafted as an issue.

Clear is the provider side of the Da Vinci prior authorization exchange. It plays the client in these tests, and Inferno plays the payer:

- **CRD**, Coverage Requirements Discovery 2.2.1: Clear calls the payer's CDS Hooks services.
- **DTR**, Documentation Templates and Rules 2.2.0: Clear fetches and completes the payer's questionnaires.
- **PAS**, Prior Authorization Support 2.2.1: Clear submits the prior authorization request.

## Read this first

- **All data is synthetic.** Every patient, clinician, payer and order in these runs is made up. No patient data is in this repository, and none was used to produce it.
- **These are local runs, not certification.** We ran the official kits on our own machine, at the pinned versions below. No test lab, ONC, Drummond or MITRE has reviewed them. Nothing here claims certification or conformance beyond the results shown.
- **Some tests were released by script.** Some Inferno tests wait for a person to attest, for example "the questionnaire was shown and the response saved". In these runs a script released those waits from Clear's recorded state. Each one is labelled "attested by script" below and in `results.json`. They are not observed conformance. A person must confirm them in the Inferno interface before results are submitted anywhere.
- **Results are as observed.** A failure stays a failure until a later run passes it. Each failure names who fixes it: Clear (with its MetaCare ticket), or a test kit or guide (with the defect id in this repository).

## How to read the results

Each guide's section gives the latest run, what was tested and the counts. Inferno reports each test as one of:

- **pass** or **fail**;
- **error**: the test itself raised an error;
- **skip**: the test ran but had nothing to check;
- **omit**: the test does not apply;
- **not run**: the test was not started, for example because it belongs to a security option Clear did not use in that run.

"Clear tested" names the Clear branch and commit, and the pull requests it included. Clear's source is private. The commit ids let a reviewer match a result to a version we can show on request.

Totals count every test in the suite, including tests for options a run did not use. The tables below say why each test that did not pass did not pass.

## Kit defects: how they are reported

Each defect has a drafted issue in [`defects/`](defects). A draft gives the repository it belongs to, the kit version and commit, the test, a reproduction, the expected and actual behavior, the source lines and a proposed fix. Where we could, the fix is on a branch of our fork of the kit, with a test in the kit's own framework:

- [metacareforyou/davinci-dtr-test-kit](https://github.com/metacareforyou/davinci-dtr-test-kit)
- [metacareforyou/davinci-crd-test-kit](https://github.com/metacareforyou/davinci-crd-test-kit)
- [metacareforyou/us-core-test-kit](https://github.com/metacareforyou/us-core-test-kit)

**Nothing is filed upstream until our internal testing is done and MetaCare approves each issue.** The `inferno-issue` skill in [`.claude/skills/inferno-issue`](.claude/skills/inferno-issue/SKILL.md) files an approved draft. It runs as a dry run by default and records the filed link back into the draft and this page.

### For ONC and Drummond

ONC and Drummond get the same list as the kit maintainers, at the same time:

1. The table of defects above is the list. Each row links to the full draft.
2. When a defect is filed upstream, its row links to the filed issue, so the list always shows the current state.
3. For a submission, we send this repository's link at a tagged commit, so the reviewer sees exactly the list we filed from. We also attach the drafts themselves if the reviewer prefers files.

## Updating this report card

The parent Clear repository writes each run to `conformance/inferno/results/<kit>/`. To add a run:

```
node scripts/import-run.mjs --kit dtr --from <path to results/dtr> \
  --branch <Clear branch> --commit <Clear commit> --pr <number> --note "<what the run covered>"
node scripts/check-secrets.mjs
```

The import copies the run to `results/<kit>/<date>/`, removes tokens, keys, client secrets, signed JWTs, resume tokens, session ids, cookies and local addresses, scans the result again, and stops without writing anything if a match remains. It then regenerates the tables on this page from `results/`, `triage/` and `defects/`. Why a test failed or did not run is recorded in `triage/<kit>.json`, one rule per cause.

`node scripts/import-run.mjs --render` regenerates this page without importing a run. `node --test scripts/test` runs the scrubber's tests.

## Branches

`main` is the published report card. Changes go to `develop` by pull request, and `develop` is merged to `main` when a set of results is ready to publish.
